# Technology Exploration Within the Lifecycle

Enter at ASSESS/DESIGN in the [lifecycle backbone](LIFECYCLE_VALUE_STREAM.md): compare candidates → bounded experiment if needed → evidence-backed decision → controlled implementation → observed outcome/revisit.

Compare relevant capabilities and costs: user fitness, interoperability, security, latency, resources, maintainability, licenses, skills and reversibility. No language, vendor or architecture receives automatic preference. Use experiments only when uncertainty warrants them under [open technology principles](OPEN_TECHNOLOGY_PRINCIPLES.md); ordinary alternatives need a short rationale.

Apply the [adoption evidence contract](../02_STANDARD/INTEROPERABILITY_NEUTRALITY.md) and route subsequent work through [feedback](OPERATIONAL_FEEDBACK_LOOP.md).

Radar review is optional, triggered by an incident, deprecation, capability gap, cost change or architecture review. A marketplace, monitoring daemon or automatic upgrader is unnecessary without a demonstrated need.
